`t.localizations(key, params)` takes a message with `{params}` and fills them into each locale's translation, where that translation places them, so descriptions that differ by one word need one catalog key, not one per word. The params are typed from the default message, as `t()`'s are. A value is a word or a number, used in every locale, or a function of the locale for a value that is itself translated: `t.localizations('lookup.user', { mode: locale => t.locale(locale)('modes.chaos') })`. The function is called once for each locale whose message uses it. A value, static or from a function, is used as written: a `{param}` in it stays as text, as `t()` leaves it. A translator typed `Translator<any>`, or by hand with messages typed `string` (a JSON file's shape), takes any params for such a message. A param the default message takes and `params` leave out, or give as `undefined`, throws, naming each one. `t.localizations(key)` without params is unchanged; for a message that takes params, its error now names the params to give. `ParamLocalizationKey`, `LocalizationParam` and `LocalizationParams` are exported from `meocord/common`, to type a helper that takes such a key or builds its params before passing them on. See [Localisation](https://meocord.dev/docs/4.3/localisation).
