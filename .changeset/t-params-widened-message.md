`t(key, params)`, `t.default`, `t.locale(l)`, `t.for(…)` and `t.forGuild(…)` take params for a message typed `string`, as in a translator typed `Translator<any>` or typed by hand from a JSON file's shape, and a plural whose forms are typed `string` takes params besides its `count`. Such a call failed to compile, though it fills its params at run time. A translator now also assigns to one typed with a catalog of plurals written by hand, such as `Record<string, { one: string; other: string }>`, whose forms typed `string` take any params beside `count`. Params stay optional for a message typed `string`, and a plural still requires its `count`. `Translator<never>`, as `createTranslator(… as never)` gives, takes any params on any key, where the published types refused the call. So does `Translator<Record<string, never>>`. Neither is a catalog type anyone writes, and every assignment of either, and every reader of their key types, compiles as before. `Translator<Record<string, never>>`, a translator of an empty catalog and one of a union of catalogs that share no key also assign to a translator typed with any catalog, since they take any params; none of the three has a message a call could read. Calls that compiled before still do. `MessageParams` of a message typed `string` is any params, so a type reading `keyof MessageParams<string>` sees `string`. See [Localisation](https://meocord.dev/docs/4.3/localisation).
