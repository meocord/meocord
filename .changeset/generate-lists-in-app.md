'meocord': minor

`meocord generate controller` and `meocord generate observer` now add the class they write to `src/app.ts`: its import after your last import, and its entry in `@MeoCord({ controllers })` or `@MeoCord({ observers })`, adding `observers` when the options have none. A controller or observer takes no part until it is listed, and the step was easy to miss. The edit is made with your project's own `typescript` and inserts only those lines, following the list's layout, indentation and trailing comma; nothing else in the file changes. When your project has ESLint, found from its root as Node finds packages, including one a workspace keeps in a parent folder, the edited file is linted with it, with no fixing, as your app's lint runs it; an edit that would bring an error the file didn't have, such as an import a rule forbids or a line past Prettier's print width, is undone, and the file is left as it was, its modification time included. The file is written in place, as an editor saves it: its mode, owner and links stay, a symlinked `src/app.ts` edits its target, and one you can't write is refused. Because a typed ESLint config lints the file on disk, the edit is there while it is checked, so `start --dev` rebuilds twice for an edit that is undone, and three times for one kept in a file that already had lint errors. Ctrl+C, or a SIGTERM outside Windows, while the edit is being checked puts the file back first. When ESLint is missing, can't run or doesn't finish, the class is listed and `generate` says it went unchecked and why. Pass `--skip-app` to keep the old behaviour, which leaves `src/app.ts` alone and prints what to add.

When the class can't be placed safely, `generate` writes its files, warns why, prints the two lines to add and changes nothing in `src/app.ts`: when the file or its `@MeoCord({ … })` is missing; the list is not an array written in place (a variable, an import or a call) or holds a spread; the options have a spread or a computed key that may already hold the list; the class's name is already taken in `src/app.ts`, by a type-only import, an import from another file or a declaration of its own; the edit would fail your lint; or the project's `typescript` can't be loaded or has no compiler API on its main entry, as with TypeScript 7. A class already imported and listed is left alone. Other kinds, such as services and guards, are used by naming them in code and keep printing their hint. ESLint gets 60 seconds across the runs `generate` makes, including the one that formats the files it writes: a run still going then is stopped, and killed if it ignores the request, no further run starts, and a warning says the files went unformatted or the edit unchecked, so a config that never finishes no longer holds `generate` for good. Its report is read from a file of its own, so a config that prints does not leave the edit unchecked. See [CLI](https://meocord.dev/docs/4.3/cli).
